Attention-free sequence models: what the architecture search actually shows

A guide to the reported results, the code behind them, and the limits of comparing a searched architecture with a transformer on short synthetic tasks.

A note from Intelligence Research Project · Published September 21, 2026

This note summarizes the project's published artifacts. It does not report a new benchmark run or an independent replication.

ResultsMechanismsLimitsReproduceCite

The question behind the experiment

Can a sequence model preserve and combine information without attention-based routing? The project first explored manually designed models, then randomly sampled 3,000 candidate architectures from a library of propagation and state-update mechanisms. The search evaluated 2,989 candidates successfully and promoted 298 to a 200-step evaluation.

The selected model, arch_2334, has 103,500 parameters. It outperformed the reported transformer reference on each of the three evaluated synthetic tasks. That observation motivates further experiments; it does not establish a general replacement for transformers.

Source: repository results and experimental setup, pinned to revision ed19559.

Do not mix the search score with the final comparison

The search analysis lists arch_2334 with an average accuracy of 0.9772, while the README comparison table reports 97.6%. These are separate reported values. The repository explicitly notes that joint training during search differs from per-task evaluation in the final benchmark, and rankings may change with the protocol.

The summary table does not provide uncertainty intervals. The 32.8-point average difference is a descriptive comparison, not a significance test or an estimate of performance on natural language.

What the search selected

The winning model combines local hash-bucket exchange, hierarchical pooling, depthwise and dilated convolutions, and a spectral filter. Its state updates include Conv-GRU, squeeze-excite, polynomial activation, and per-channel scaling.

GatedShiftMixer, the mechanism behind the earlier manually designed AFN v3, is absent from the selected architecture. This suggests that several combinations of simpler mechanisms can support the information transfer required by these tasks. It does not show that any individual mechanism is unnecessary across other tasks.

Most of the selected propagation mechanisms scale linearly with sequence length; the FFT-based spectral component scales as O(L log L). Calling the whole architecture strictly O(L) would hide that distinction.

Five boundaries on the claim

  1. Short, synthetic tasks. The result covers three constructed tasks at lengths 32–64. It does not report natural-language perplexity or establish long-context language-model performance.
  2. One baseline family. The reported comparison does not include Mamba, RWKV, or Hyena under a matched budget.
  3. Search cost is additional compute. Matching model size and final training steps does not account for the cost of exploring 3,000 candidates.
  4. Routing can be non-causal. The repository warns that circular torch.roll shifts wrap sequence boundaries and that future-direction masking for autoregressive use is not implemented. Inspect causality before transferring these mechanisms to next-token prediction.
  5. Protocols differ. Joint search training and per-task final evaluation are not interchangeable. Re-running the benchmark is necessary to assess how stable the ranking is under different settings.

These boundaries are central to interpreting the result. See the source limitations and the site's evaluation standards.

Inspect and reproduce the comparison

The repository specifies Python 3.10+, PyTorch 2.0+, NumPy, and pytest. The following commands select the same source revision used in this note. Dependency resolution and the execution environment can still affect reproducibility; inspect the requirements and code before running.

git clone https://github.com/sunghunkwag/attention-free-sequence-model.git
cd attention-free-sequence-model
git checkout ed1955973c10f6cfeef61a0139d9d13fc8d13812
python -m pip install -r requirements.txt
python -m pytest tests/ -v
python benchmarks/search_benchmark.py

To repeat the architecture search itself, the repository documents python -m architectures.search_engine --n_trials 3000. This is a separate, larger computation than running the final three-model benchmark.

  • Benchmark implementation: inspect the task generators, transformer baseline, and evaluation loop.
  • Full search log: inspect candidate outcomes rather than relying only on the winner.
  • Search analysis: review failures and mechanism frequencies.
  • Source README: review the current scope at the cited revision.

For a useful replication, record the source revision, dependency versions, random seeds, hardware, task protocol, and complete results, including failures.
