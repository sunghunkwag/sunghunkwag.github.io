Recursive self-improvement, measured against the right control

Inspect reported matched-compute RSI results across two environments, the repaired mechanism, baseline limitations, downloadable data, and pinned source evidence.

A note from Intelligence Research Project · Published September 23, 2026

This note explains published project artifacts. It does not report a new benchmark run or an independent replication.

The question is a difference, not a headline

The gated-self-improvement project investigates bounded improvement loops in deterministic, LLM-free Python systems. This experiment asks whether five recursive rounds outperform a single round given five times the compute. That is a narrower question than whether the resulting system beats an untrained baseline. The RSI test checklist explains why the comparator matters.

The pinned RSI Upgrade report describes a repaired mechanism and confirmatory holdouts: 40 local runs and 60 Kaggle runs. The repository overview explains held-out tasks, matched budgets, and identical random streams for counterfactual comparisons.

The first row supports the report’s advantage against the equal-compute single-round comparator. The last row does not establish superiority to the untrained baseline. These observations are compatible because they use different comparators.

Keep the environments separate. The reported +1.55 and +1.47 are not interchangeable estimates of a pooled +1.55 result. This note does not compute a pooled significance test or new confidence intervals from summary values.

What changed after the harmful chain

The source reports that the original chain reduced performance relative to the untrained baseline. It identifies a noisy partial-fitness pool, entropy collapse from occurrence counts, and insufficient step control, then describes four repairs:

  1. Credit only solved outcomes and remove duplicate credit.
  2. Use presence-based, level-stratified targets.
  3. Constrain updates with a trust region and an entropy floor.
  4. Require generalization checks for acceptance and roll back failed changes.

Read the implementation at the cited revision alongside the table. This summary does not isolate the contribution of each repair; that requires the relevant ablations and run artifacts.

What the evidence does not establish

The report concerns bounded tasks in a particular experimental substrate. It does not establish open-ended recursive improvement, general intelligence, or a general advantage for self-modifying systems. The source also reports a null for its meta-RL grid at the full configuration.

The two environments are project-reported runs, not independent replications. The summary table is insufficient to recompute uncertainty: consult run records, task definitions, and the statistical procedure before making a stronger inference. A non-significant result is not proof that two systems are equivalent.

For complementary measurement questions, see the RSI-Bench methods note. For architecture-search evidence, see the attention-free sequence-model results.
